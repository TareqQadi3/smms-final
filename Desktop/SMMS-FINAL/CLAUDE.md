# دليل التطوير التقني - نظام إدارة الصيانة

هذا الملف هو المرجع الأساسي (Source of Truth) للقواعد البرمجية، منطق العمل، والصلاحيات. **يجب على Claude الالتزام بهذه القواعد في كل كود يتم توليده.**

## 1. قواعد الصلاحيات (RBAC) - القاعدة الذهبية: "لا تعتمد على الواجهة"
- **التحقق من الخادم (Server-Side Enforcement):** يجب التحقق من صلاحية المستخدم في الـ Backend قبل تنفيذ أي عملية (CRUD). إخفاء الأزرار في الواجهة (Frontend) هو مجرد تحسين لتجربة المستخدم، وليس إجراءً أمنياً.
- **عزل البيانات (Data Isolation):**
    - الفنيون (Technicians): يجب أن تتضمن جميع استعلامات الـ SQL أو الـ Queries شرطاً يحد النتائج بناءً على `user_id` الخاص بالفني.
    - الصلاحيات: Admin يرى الكل، الفني يرى ما يخصه فقط.
- **تجنب الخطأ:** لا تقم أبداً بتوليد كود يتيح للمستخدم الوصول إلى أوامر عمل ليست ضمن نطاق صلاحياته.

## 2. منطق العمل (Business Logic) - قواعد المعاملات (Atomic Transactions)
- **سلامة البيانات (Data Integrity):** أي عملية تشمل (إضافة قطعة غيار + تحديث حالة أمر العمل) يجب أن تتم داخل `Transaction` واحد. إذا فشل أي جزء، يتم إلغاء العملية بالكامل (Rollback).
- **التحقق من المخزون:** قبل أي خصم لقطع الغيار، يجب تنفيذ فحص `IF (stock_quantity >= required_quantity)`.
- **التسلسل الزمني:** يمنع منعاً باتاً السماح بحفظ "تاريخ إغلاق" أمر العمل قبل "تاريخ فتحه". يجب إضافة Validation دائماً.

## 3. معايير كتابة الكود (Code Standards)
- **البرمجة النظيفة:** تجنب تكرار الكود (DRY Principle). إذا وجدت تكراراً في منطق التحقق من الصلاحيات، قم بإنشاء Middleware خاص به.
- **التوثيق:** أي دالة (Function) تتعلق بـ "حالة أمر العمل" أو "خصم قطع غيار" يجب أن تحتوي على تعليق يشرح المنطق الرياضي أو الشرطي المستخدم.
- **معالجة الأخطاء:** لا تترك الـ `catch blocks` فارغة. يجب إرجاع رسالة خطأ واضحة للمستخدم وتسجيل الخطأ البرمجي في سجلات النظام.

## 4. جدول الصلاحيات المرجعي (RBAC Matrix)
| الدور | العمليات المسموحة |
| :--- | :--- |
| **Admin** | كل شيء (CRUD شامل) + إدارة المستخدمين. |
| **Manager** | عرض التقارير + الموافقة على أوامر العمل. |
| **Technician** | عرض أوامر العمل المسندة له + تحديث الحالة + تسجيل قطع الغيار المستخدمة. |
| **Viewer** | عرض (Read Only) للبلاغات فقط. |

## 5. تعليمات التكرار (تنبيه هام)
- إذا واجهت خطأً متكرراً في تنفيذ صلاحيات أو منطق العمل، توقف عن اقتراح حلول جديدة، وقم بمراجعة هذا الملف أولاً.
- التزم بهيكلية المجلدات الحالية ولا تقم بإنشاء ملفات عشوائية إلا إذا كانت ضرورية جداً.

## 6. سير العمل للمهام الصعبة (تفضيل المستخدم)
- للمهام الصعبة: التخطيط والتحليل وتقييم المخاطر يتم بنموذج Claude Opus 5.5 فقط ودون تنفيذ.
- بعد اكتمال الخطة واعتمادها يتم التنفيذ (كود، تثبيت، اختبارات، توثيق) بنموذج Claude Sonnet 5.5 فقط.
- يجب التحقق من توفر النموذج فعلياً وعدم الاستبدال بصمت بنموذج آخر.
- في هذه الجلسة تم ذلك بأن عمل النموذج الرئيسي Opus 5.5 كمخطط، وتم تفويض التنفيذ لوكلاء فرعيين بنموذج sonnet (أكدوا أن معرّف النموذج claude-sonnet-5-5).
